# Репозиторий backend по курсу "Разработка интернет-приложений"

## Общее описание

Этот backend предоставляет API для работы с нагрузками перекрытий: создание черновика, публикация, фильтрация, лайки, удаление и базовая авторизация по заглушке текущего пользователя.

В проекте используется фиксированный текущий пользователь-создатель:

- `id = 1`
- имя: `creator`

Это значение задаётся как singleton-функция `getCurrentCreatorUserId()` и используется во всех методах, где требуется привязка к текущему пользователю.

## Общие правила контракта

- Все методы, связанные с текущим пользователем, используют `creator_id = 1`.
- Для полей-флагов `is_owner` и `is_liked` используются значения `0` или `1`.
- Для лайков используется поле `like`:
  - `1` — поставить лайк
  - `0` — снять лайк
- Для загрузки изображений и коротких видео используется `multipart/form-data`.
- Файлы не сохраняются в БД как URL; в БД сохраняются только имена файлов, сами файлы хранятся в MinIO.

## 1. Пользователи

### 1.1. POST /users/register

Создаёт нового пользователя.

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| name | string | Да | Имя пользователя |
| password | string | Да | Пароль |

Пример ответа:

```json
{
  "id": 2,
  "name": "alice"
}
```

### 1.2. POST /users/login

Логин текущего пользователя (заглушка).

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| name | string | Да | Имя пользователя |
| password | string | Да | Пароль |

Пример ответа:

```json
{
  "ok": true,
  "message": "Аутентификация временно заглушена",
  "login": true,
  "user": {
    "id": 1,
    "name": "creator"
  }
}
```

### 1.3. POST /users/logout

Выход из системы (заглушка).

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| — | — | — | Тело запроса отсутствует |

Ответ:

- HTTP `204 No Content`

## 2. API нагрузок

Базовый префикс: `/api/floor-loads`

### 2.1. GET /api/floor-loads

Получает список только опубликованных услуг.

| Поле | Тип | Описание |
| --- | --- | --- |
| id | number | Идентификатор услуги |
| title | string | Заголовок |
| description | string \| null | Описание |
| standard_load | number \| null | Нагрузка |
| reliability_coefficient | string \| null | Коэффициент надёжности |
| image | string | Имя файла изображения |
| video | string | Имя файла видео |
| likes | number[] | Список идентификаторов лайков |
| is_owner | number | `1`, если текущий пользователь владелец; иначе `0` |
| is_liked | number | `1`, если текущий пользователь лайкнул; иначе `0` |

Пример ответа:

```json
[
  {
    "id": 1,
    "title": "Перекрытие 6 м",
    "description": "Описание услуги",
    "standard_load": 120,
    "reliability_coefficient": 0.9,
    "image": "image-123.jpg",
    "video": "video-456.mp4",
    "likes": [12, 35],
    "is_owner": 1,
    "is_liked": 0
  }
]
```

### 2.2. GET /api/floor-loads/load/:id

Получает опубликованную услугу по идентификатору.

Параметры:

- `:id` — числовой идентификатор услуги

Дополнительно:

- `GET /api/floor-loads/load/:id?next=true` — возвращает следующую активную услугу после указанной

### 2.3. GET /api/floor-loads/draft

Возвращает текущий черновик пользователя.

Сценарий:

- у пользователя не более одного активного черновика
- запрос не принимает `id`, а всегда берёт черновик текущего пользователя

Ответ:

```json
{
  "id": 42,
  "image": "image-123.jpg",
  "video": "video-456.mp4"
}
```

### 2.4. POST /api/floor-loads/add

Создаёт черновик с изображением и коротким видео.

Формат запроса: `multipart/form-data`

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| title | string | Да | Заголовок услуги |
| image | file | Да | Изображение (jpg/png/webp и т.п.) |
| video | file | Да | Короткое видео (mp4/webm и т.п.) |

После загрузки:

- файл сохраняется в MinIO
- в БД сохраняются только имена файлов
- создатель назначается текущему пользователю (`creator_id = 1`)

Пример формы:

```text
title=Перекрытие 6 м
image=@/path/to/image.jpg
video=@/path/to/video.mp4
```

### 2.5. PUT /api/floor-loads/add

Публикует текущий черновик текущего пользователя.

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| description | string | Да | Описание услуги |
| standard_load | string | Да | Нагрузка в виде строки, затем конвертируется в число |
| reliability_coefficient | string | Да | Коэффициент надёжности |

Пример запроса:

```json
{
  "description": "Это описание публикуемой услуги",
  "standard_load": "120",
  "reliability_coefficient": "0.9"
}
```

Логика:

- берётся последний черновик текущего пользователя
- обновляются поля `description`, `standard_load`, `reliability_coefficient`
- статус меняется на `active` (`published`)

### 2.6. POST /api/floor-loads/like

Ставить или снимать лайк текущему пользователю.

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| load_id | number | Да | Идентификатор услуги |
| like | number | Да | `1` — поставить лайк, `0` — снять |

Пример запроса:

```json
{
  "load_id": 5,
  "like": 1
}
```

### 2.7. POST /api/floor-loads/delete/:id

Удаляет нагрузку текущего пользователя.

Параметры:

- `:id` — идентификатор услуги

Логика:

- проверяется, что услуга принадлежит текущему пользователю
- если нет — возвращается ошибка доступа
- иначе услуга переводится в статус `deleted`

## 6. Примечания по файловому хранилищу

Для загруженных изображений и видео используется MinIO.

Правила:

- имена файлов генерируются на латинице;
- кириллические символы заменяются на транслит;
- пробелы и спецсимволы заменяются на `-`;
- к имени добавляется таймстамп, чтобы избежать конфликтов;
- в БД сохраняется только финальное имя файла типа `image-1234567890.jpg` или `video-1234567890.mp4`.
